## Key decisions

1. **Postgres as the job queue (an outbox), in the same transaction as dedup.** Recording the interaction,
   the report and the jobs it needs (reply, channel post, mirror) is one atomic write, keyed on Discord's
   interaction id. A duplicate delivery hits `ON CONFLICT` and can't enqueue anything twice. A downstream
   outage leaves retryable rows behind instead of a lost command.
2. **Supabase over Neon, first I'm handy with it, with compute colocated next to it.** Neon's free tier scales to zero and caps compute
   hours, which an every-minute retry sweeper would burn through. I picked Mumbai region, so the server stays near, with minimal latency.
3. **Integration tests on PGlite (real Postgres in-process), not mocks.** `ON CONFLICT`, `FOR UPDATE SKIP
   LOCKED` and leases behave for real in tests. The caveat, learned the hard way: PGlite is not the
   production driver (more details below).

## The hardest bug: "Couldn't post to the mirror", when it had posted

**What the AI got wrong.** The settings page has a "Send test message" button for the mirror. Claude wrote
the server action like this (commit `a2472a9`):

```ts
try {
  await sendMirror(decrypt(guild.mirrorUrlEnc!), { ... });
  redirectWithParam(guildId, "success", "Test message sent to the mirror.");
} catch (err) {
  log.error("test mirror post failed", { ... });
  redirectWithParam(guildId, "error", "Couldn't post to the mirror. Check the webhook is still valid.");
}
```

Next's `redirect()` works by *throwing* a special `NEXT_REDIRECT` error. The success redirect threw, the
action's own `catch` swallowed it, and the error redirect replaced it. Every successful test therefore
reported failure. The error text Claude wrote even pointed at the wrong cause ("check the webhook"). The same
bug was in the channel test button.

**Why it got through.** All 127 tests passed, and typecheck and lint were clean. No test exercised the server
actions. Claude checked the live flow by querying the jobs table, but the test button doesn't create jobs,
and Claude can't see Discord.

**How I noticed.** I clicked "Send test message" and the message arrived in the mirror channel, while the
dashboard showed the red error. Two sources disagreed.


**How it was fixed (`a7c2c8b`).** The Vercel log confirmed it: the "failure" logged was `NEXT_REDIRECT`, not
an HTTP error. Both actions now record the outcome inside the try/catch and redirect exactly once, after it.
`test/unit/settingsActions.test.ts` mocks `redirect` to throw the way the real one does and asserts a single
redirect to the success URL. Before keeping it, ran it against the old code to make sure it failed there:
the old code redirected twice and ended on the error URL.

**Some wrong turns by AI:**

- **Tests passed on PGlite, but the cron sweep returned 500 against Supabase (`3f21617`).** postgres.js can't
  bind a bare `Date` inside a transaction, and PGlite doesn't mind. Fixed by passing an ISO string cast to
  `::timestamptz`.
- **GitHub push protection blocked the first push (`1822f2f`).** For a test case, there was a fake gibberish token that Claude had written a realistic-looking fake, made some adjustments to not look like a realistic token.
- **Ugly ugly UI** At first claude, ignored ugly UI/UX. Later I asked it to atleast look a little nicer.
